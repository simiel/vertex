# Implement the offline Vertex video ingestion pipeline

## Goal

Build a deterministic, offline video ingestion pipeline that turns normalized video metadata, timestamped captions, and authored/source chapter markers into Sanity `video` documents. The output must contain one document per unique supported video URL, a clean ordered `chapters` table of contents, and short ordered `chunks` of transcript text. The pipeline must be reusable for YouTube, Vimeo, and Bunny inputs, must never run in the Next.js request path, and must not fetch or store entire transcripts in application query helpers.

## Decisions and assumptions

- The source contract is a normalized JSON manifest supplied to the CLI, not a live provider scraper. This keeps ingestion offline, repeatable, testable, and independent of provider APIs or credentials.
- The manifest contains one record per source video with a `url`, optional provider metadata, a transcript represented as timestamped caption entries, and optional chapters. A documented example fixture may be added, but the provided `videos.json` remains byte-for-byte unchanged and is not falsely treated as a transcript source.
- Provider adapters validate and canonicalize YouTube, Vimeo, and Bunny URLs and derive a stable provider/video ID. Do not claim a provider is ingestible unless its normalized input and output are supported. No network calls are added.
- Use a stable content-derived Sanity `_id` for the generated internal video document, based on a sanitized video ID. This is intentionally scoped to the pipeline’s one-document-per-video identity requirement; ordinary editorial documents remain generated by Sanity.
- Preserve the canonical source URL in `url` and store the provider/video ID in the schema’s `id` field. Do not add unrelated fields or modify lesson/course schemas.
- Normalize timestamps to non-negative integer seconds, sort chapters and transcript entries, reject invalid or duplicate chapter positions, and reject transcript entries that exceed the declared duration when duration is supplied.
- Normalize caption text by trimming whitespace, collapsing repeated whitespace, removing empty entries, and merging adjacent entries into bounded chunks. Chunks should target roughly 15–30 seconds and a safe text size, while preserving the first caption start time of each chunk. Do not merge across authored chapter boundaries when that would make a chapter match less precise.
- Chapters are clean labels: trim/collapse whitespace, remove empty labels, sort by start time, and keep the supplied order only after validating it is chronologically coherent. Prefer authored chapters; otherwise accept provider/source chapters. Do not invent chapter labels from transcript text.
- Emit Sanity-shaped JSONL/NDJSON with `_id`, `_type: "video"`, `id`, `url`, `chapters`, and `chunks`; generate stable `_key` values for array items so reruns are diffable and imports are predictable.
- Provide a dry-run/validation mode and an output mode. Do not automatically write to or delete from a dataset. If a Sanity import helper is included, it must be an explicit separate command using `sanity datasets import --replace` and must never reset the dataset.
- Keep raw inputs and generated output outside tracked source by default where practical; commit scripts, schemas/contracts, docs, and a small fixture only. Never commit credentials or real customer/source exports.

## Requirements

1. Add a small typed ingestion library under `studio/scripts/video-ingestion/` (or the closest existing Studio scripts convention) with:
   - manifest and normalized-record types;
   - provider URL parsing/canonicalization for YouTube, Vimeo, and Bunny;
   - transcript cleanup, timestamp normalization, and deterministic chunking;
   - chapter normalization and validation;
   - Sanity document transformation;
   - actionable validation errors that identify the record and field.
2. Add a CLI entry point runnable from `studio/` with explicit `--input`, `--output`, and `--check`/dry-run behavior. It must:
   - read JSON without mutating it;
   - fail non-zero on malformed JSON, unsupported providers, missing transcript timestamps/text, invalid chapter data, duplicate video identities, or records with no usable transcript/chapter data;
   - print counts and a concise validation summary without printing secrets or whole transcripts;
   - produce stable output regardless of input record order.
3. Define and document the normalized input format, including examples for captions and chapters, provider-specific URL expectations, duration units, and how authored chapters take precedence.
4. Add focused tests or an executable fixture check covering:
   - YouTube URL variants and stable identity;
   - Vimeo and Bunny URL parsing;
   - whitespace/empty-caption cleanup;
   - adjacent-caption chunk merging and chunk bounds;
   - chapter ordering/clean labels;
   - invalid timestamps and duplicate identities;
   - deterministic output and Sanity document shape.
5. Add or update only the necessary package scripts/dependencies. Prefer the installed Node 22/TypeScript runtime and existing dependencies; avoid adding a network scraper or heavyweight media dependency unless the repo already requires it.
6. Keep the existing `video` schema compatible. If schema validation needs tightening, use `defineType`, `defineField`, and `defineArrayMember`, include array keys in generated documents, and explain any schema change in the implementation.
7. Add operator documentation with the exact commands for check, generate, inspect, and (if provided) import. Include the expected follow-up verification query for counts and sample documents.

## Security and boundaries

- The pipeline is offline tooling only. No ingestion code may be imported by `app/`, route handlers, or request-time Sanity helpers.
- Do not download video media, scrape provider pages, or log API keys/cookies/tokens.
- Do not read `.env.local` into logs or commit generated secrets.
- Treat input JSON as untrusted: validate URLs, timestamps, lengths, and record uniqueness before emitting documents.
- Do not emit the whole transcript as a single field. The only transcript payload in a document is bounded timestamped `chunks[]`.
- Do not alter `studio/scripts/seed/videos.json` or `studio/scripts/seed/seed.ndjson`.
- Do not run a bulk Sanity write as part of tests or the default CLI. Dataset import remains an explicit operator action after reviewing generated output.

## Acceptance criteria

- A documented normalized manifest can be checked and transformed entirely offline.
- Output is valid deterministic NDJSON with one internal Sanity `video` document per unique video identity.
- Every emitted document has non-empty ordered chapters or chunks, timestamped integer seconds, bounded transcript chunks, stable `_key` values, and the exact schema field names.
- YouTube, Vimeo, and Bunny URL identities are parsed and validated; malformed/unsupported records fail clearly.
- Chapter markers are preferred over transcript matches by preserving clean authored/source chapters; no chapter labels are invented.
- Re-running the command with the same input produces byte-for-byte identical output, regardless of manifest record order.
- Existing seed files are unchanged and no web request path imports the pipeline.
- Typecheck, lint, and the focused ingestion tests/fixture check pass. A production build is run if any shared schema or application module changes.

## Checks to run after approval

1. From `studio/`, run the focused ingestion test/check command.
2. From `studio/`, run `npm run typecheck`.
3. From the repository root, run `npm run lint` and `npm run typecheck`.
4. Run a dry-run against the small fixture and generate output to a temporary path.
5. Run the generator twice and compare outputs byte-for-byte.
6. Run `git diff --check` and verify the two supplied seed files have no diff.
7. If schema code changes, run the Studio build and root production build.
8. If Sanity credentials are available, do not import automatically; report the exact explicit import and post-import verification commands for the operator.

## Exact manual test steps

1. Create or use a normalized manifest containing one YouTube, one Vimeo, and one Bunny record with captions and chapters.
2. Run the documented `--check` command and confirm the summary reports all records valid without printing transcript bodies.
3. Generate NDJSON into a temporary output path.
4. Inspect a document and confirm `_type`, stable `_id`, provider `id`, canonical URL, ordered chapter markers, and short timestamped chunks.
5. Reorder the manifest records, generate again, and confirm the outputs are identical.
6. Introduce an invalid URL, negative timestamp, duplicate identity, and empty transcript one at a time; confirm each fails with a field-specific non-zero error.
7. Confirm `studio/scripts/seed/videos.json` and `studio/scripts/seed/seed.ndjson` remain unchanged.
8. After reviewing the generated file, optionally import it explicitly with the documented Sanity CLI command and query `_type == "video"` to verify counts and representative documents.
